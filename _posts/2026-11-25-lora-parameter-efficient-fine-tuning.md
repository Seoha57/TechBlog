## 먼저 답하기

### Q. LoRA는 무엇인가요?

A. LoRA(Low-Rank Adaptation, 저랭크 적응)는 이미 학습된 대형 언어 모델의 가중치(weight, 모델이 학습으로 얻은 숫자들)를 그대로 얼려 두고, 그 옆에 아주 작은 행렬 두 개를 덧붙여 그 작은 행렬만 학습하는 미세 조정(fine-tuning, 이미 학습된 모델을 특정 용도에 맞게 추가 학습하는 일) 기법입니다. 2021년 Hu 등이 발표한 논문에서 제안되었습니다. 학습해야 할 숫자가 원래 모델의 아주 일부이므로 GPU 메모리와 저장 공간이 크게 줄어듭니다. 이 글은 논문과 공식 문서를 바탕으로 정리한 학습 자료이며, 제가 직접 모델을 학습시켜 측정한 결과가 아닙니다. 코드는 라이브러리 문서의 사용법을 따른 예시이므로 실제 환경에서는 버전과 하드웨어에 맞게 확인하세요.

### Q. 전체 미세 조정과 무엇이 다른가요?

A. 전체 미세 조정(full fine-tuning)은 모델의 모든 가중치를 갱신하므로 가중치뿐 아니라 갱신에 필요한 부가 정보(기울기와 옵티마이저 상태)까지 메모리에 올려야 하고, 결과물도 모델 전체 크기의 새 복사본이 됩니다. LoRA는 원래 가중치를 고정하고 작은 어댑터(adapter, 기존 모델에 덧붙이는 작은 학습 모듈)만 저장하므로 결과물이 수 MB에서 수백 MB 수준으로 작아질 수 있고, 같은 기본 모델 위에 용도별 어댑터를 바꿔 끼울 수 있습니다. 구체적인 비교는 아래 「전체 미세 조정과 비교」 표를 보세요.

### Q. 그럼 항상 LoRA로 학습하면 되나요?

A. 아닙니다. 모델이 새 지식을 많이 습득해야 하거나 기본 모델과 크게 다른 영역이면 LoRA의 표현력 한계에 부딪힐 수 있습니다. 또 사실 정보를 최신으로 유지하는 문제는 미세 조정보다 검색 증강(RAG)이 더 맞는 경우가 많습니다. 어떤 문제에 어떤 방법이 맞는지는 아래 「한계와 적용 기준 Q&A」에서 정리합니다.

## 먼저 알아둘 기반 기술

이 절은 본문을 읽기 위한 지식을 가장 밑바닥(행렬과 랭크)에서 LoRA 직전(미세 조정의 메모리 구조)까지 순서대로 쌓습니다. 각 소절 끝에는 본문에서 다시 쓰이는 위치를 적었고, 절 마지막에 연결 지도를 표로 정리했습니다.

### 행렬과 랭크

행렬(matrix)은 숫자를 행과 열로 늘어놓은 표입니다. 신경망에서 입력 벡터(숫자 목록)에 행렬을 곱하면 다른 벡터로 변환되며, 이것이 신경망의 기본 계산입니다. 행렬의 랭크(rank, 계수)는 그 행렬이 가진 "독립적인 정보 방향의 개수"입니다. 예를 들어 4행 4열 행렬이어도 모든 행이 첫 행의 배수라면 사실상 정보는 한 줄뿐이므로 랭크가 1입니다. 큰 행렬이라도 랭크가 낮으면 훨씬 작은 두 행렬의 곱으로 정확히 표현할 수 있습니다. 가로세로 `d × d` 행렬을 `d × r` 행렬과 `r × d` 행렬의 곱으로 나누면 숫자는 `d²`개에서 `2dr`개로 줄어듭니다.

```python
import numpy as np
d, r = 6, 1
B = np.random.randn(d, r)      # 6x1
A = np.random.randn(r, d)      # 1x6
W_delta = B @ A                # 6x6 행렬이지만 랭크는 1
print(np.linalg.matrix_rank(W_delta))   # 1
print(d*d, 2*d*r)                       # 36 vs 12
```

LoRA의 핵심 아이디어가 바로 "가중치가 바뀌어야 하는 양은 저랭크 행렬로 충분히 표현될 수 있다"는 가정입니다. 이 개념을 모르면 LoRA가 왜 숫자를 그렇게 많이 줄이면서도 동작하는지 이해할 수 없습니다. 이 개념은 아래 「LoRA의 핵심 아이디어」 절에서 두 행렬 곱으로, 「파라미터 수 계산」 절에서 절감량 계산으로 쓰입니다.

### 신경망의 가중치와 트랜스포머의 어텐션 투영

신경망의 가중치(weight)는 학습 중에 조정되는 숫자이며, 모델의 "지식"이 저장되는 곳입니다. 대형 언어 모델(LLM, Large Language Model)은 대부분 트랜스포머(Transformer) 구조이며, 각 층에는 어텐션(attention, 문장 안에서 어떤 단어가 어떤 단어에 주목할지 계산하는 장치)과 피드포워드(feed-forward, 각 위치를 개별 변환하는 부분)가 있습니다. 어텐션은 입력에서 쿼리(Q), 키(K), 밸류(V)를 만들기 위해 각각 선형 변환(행렬 곱)을 하는데, 코드에서 `q_proj`, `k_proj`, `v_proj`, `o_proj` 같은 이름의 가중치가 이 변환입니다. 그 뒤의 피드포워드 부분에도 `gate_proj`, `up_proj`, `down_proj` 같은 큰 행렬들이 있습니다.

LoRA는 이 행렬들 중 어느 것에 어댑터를 붙일지 고릅니다. 이름을 모르면 설정의 `target_modules`가 무엇을 가리키는지 알 수 없습니다. 모델마다 이름이 다르므로 실제 모델을 출력해서 확인하는 습관이 필요합니다. 이 개념은 아래 「어디에 붙이고 어떤 값을 정하나」 절에서 `target_modules` 선택으로, 「실습 예시」 절에서 모듈 이름 확인 코드로 이어집니다.

### 학습과 기울기(경사하강법과 역전파)

모델 학습은 "예측이 얼마나 틀렸는지"를 손실(loss)이라는 숫자로 측정하고, 이 손실이 줄어드는 방향으로 가중치를 조금씩 고치는 과정입니다. 어느 방향으로 얼마나 고칠지는 기울기(gradient)로 계산하며, 이를 출력에서 입력 쪽으로 거슬러 계산하는 방법이 역전파(backpropagation)입니다. 기울기를 따라 조금씩 내려가며 최적값을 찾는 것이 경사하강법(gradient descent)이고, 한 번에 고치는 크기를 학습률(learning rate)이라 합니다. 등산으로 비유하면 안개 속에서 발밑 경사만 보고 한 걸음씩 내려가는 것이고, 학습률은 보폭입니다.

중요한 점은 기울기를 계산하고 저장하는 대상이 "학습 가능한(trainable) 가중치"라는 것입니다. 고정된(frozen) 가중치에는 기울기를 저장할 필요가 없습니다. 이것이 LoRA가 메모리를 아끼는 출발점입니다. 이 개념은 아래 「LoRA의 핵심 아이디어」 절에서 W를 고정하고 A·B만 학습하는 구조로, 「실습 예시」 절의 학습률 설정으로 쓰입니다.

### 미세 조정의 메모리 구조

전체 미세 조정에서 GPU 메모리에 올라가는 것은 모델 가중치, 기울기, 옵티마이저 상태, 그리고 중간 계산값(activation)입니다. 옵티마이저(optimizer)는 기울기를 받아 가중치를 갱신하는 알고리즘이며, 널리 쓰이는 Adam 계열은 가중치마다 두 개의 보조 값(모멘텀 통계)을 따로 저장합니다. 그래서 학습 가능한 가중치 한 개당 가중치 자신, 기울기, 보조 값 두 개로 대략 네 배의 숫자를 들고 있어야 하고, 정밀도에 따라 더 늘어납니다. 모델이 수십억 개의 숫자라면 이 비용이 GPU 한 장의 메모리를 쉽게 넘깁니다.

LoRA는 학습 대상이 전체의 1퍼센트 안팎이므로 기울기와 옵티마이저 상태가 그만큼만 필요합니다. 다만 고정된 원래 가중치는 여전히 메모리에 올라가야 하고, 중간 계산값은 크게 줄지 않는다는 점을 기억해야 합니다. 그래서 "LoRA를 쓰면 메모리 걱정이 없다"는 말은 과장입니다. 이 개념은 아래 「전체 미세 조정과 비교」 표에서 항목별 비교로, 「QLoRA와의 관계」 절에서 고정 가중치를 더 작게 저장하는 방법으로 이어집니다.

### 가중치 저장 정밀도와 양자화

모델의 숫자는 보통 16비트 부동소수점(fp16 또는 bf16)으로 저장하며, 숫자 하나가 2바이트입니다. 70억(7B) 개 파라미터 모델이면 가중치만 약 14GB입니다. 양자화(quantization)는 숫자를 더 적은 비트(8비트, 4비트)로 표현해 메모리를 줄이는 기법입니다. 이 블로그의 「LLM 양자화와 GGUF 입문」 글이 추론용 양자화를 다뤘다면, 여기서는 "고정된 원래 가중치를 양자화해 두고 그 위에 어댑터를 학습"하는 활용이 중요합니다.

이 개념을 모르면 QLoRA가 LoRA와 무엇이 다른지 구분하기 어렵습니다. 이 개념은 아래 「QLoRA와의 관계」 절에서 4비트로 고정 가중치를 저장하는 조합으로 쓰입니다.

## LoRA의 핵심 아이디어

사전학습된 가중치 행렬을 `W`라 하고 미세 조정으로 바뀌어야 하는 양을 `ΔW`라 하면 전체 미세 조정은 `W' = W + ΔW`를 직접 학습합니다. LoRA 논문은 이 `ΔW`가 매우 낮은 랭크를 가진다는 가설에서 출발합니다. 그래서 `ΔW`를 직접 학습하지 않고 두 작은 행렬의 곱 `B·A`로 두고, `W`는 고정한 채 `A`와 `B`만 학습합니다. 앞서 기반 기술에서 본 랭크 개념 그대로, `A`는 `r × d`, `B`는 `d × r` 크기이며 `r`(rank)은 8이나 16처럼 아주 작은 수입니다.

<figure class="article-figure"><img src="{{ '/assets/images/lora-low-rank-adapter.svg' | relative_url }}" alt="입력 x가 고정된 가중치 W와 학습 가능한 작은 행렬 A, B의 두 경로를 지나 출력이 더해지는 LoRA 구조"><figcaption>그림. W는 고정하고, A(r×d)와 B(d×r)만 학습하여 두 경로의 출력을 더한다. 이미지 출처: 직접 제작</figcaption></figure>

순전파(forward pass, 입력에서 출력을 계산하는 과정)는 `h = W·x + (α/r)·B·A·x`로 계산됩니다. `α`(alpha)는 어댑터 출력의 크기를 조절하는 배율이며, `α/r`이 실제 스케일입니다. 초기화도 중요합니다. 논문은 `A`를 무작위 가우시안 값으로, `B`를 0으로 초기화합니다. 그래서 학습 시작 시점에는 `B·A = 0`이 되어 모델이 사전학습 상태와 정확히 같게 출발하고, 학습이 진행되면서 서서히 달라집니다. 갑자기 모델이 망가진 상태로 시작하지 않는다는 점이 안정적인 학습에 도움이 됩니다. 앞서 본 학습 개념으로 말하면 기울기는 `A`와 `B`에 대해서만 계산하고 저장하며, `W`에는 기울기를 만들지 않습니다.

## 파라미터 수 계산

숫자로 확인해 봅시다. 어텐션 투영 행렬 하나가 `4096 × 4096`이라면 파라미터는 `4096² = 16,777,216`개입니다. `r = 8`의 LoRA를 붙이면 `A`는 `8 × 4096 = 32,768`개, `B`는 `4096 × 8 = 32,768`개로 합계 65,536개이며 원래의 약 0.39%입니다. 만약 32개 층 각각의 `q_proj`와 `v_proj` 두 곳에만 붙인다면 `32 × 2 × 65,536 = 4,194,304`개(약 420만 개)가 학습 대상입니다. 70억 파라미터 모델에서 약 0.06%에 해당합니다. 위 숫자는 행렬 크기를 가정한 계산 예시이며 실제 모델의 구조(예: 그룹 쿼리 어텐션으로 `k_proj`·`v_proj`가 더 작은 경우)에 따라 달라집니다.

```python
d, r, layers, mats = 4096, 8, 32, 2
full = d * d
lora = 2 * d * r
print(full, lora, round(lora / full * 100, 2))   # 16777216 65536 0.39
print(layers * mats * lora)                      # 4194304
```

`r`을 두 배로 키우면 어댑터 파라미터도 정확히 두 배가 됩니다. 이처럼 `r`은 표현력과 비용을 맞바꾸는 다이얼입니다. LoRA 논문은 일부 과제에서 매우 작은 `r`로도 충분한 성능을 보고했지만, 이것이 모든 과제에서 성립한다는 보장은 아니므로 자신의 데이터로 실험해야 합니다.

## 어디에 붙이고 어떤 값을 정하나

설정에서 정해야 할 주요 값은 네 가지입니다.

| 설정 | 의미 | 시작할 때의 일반적 접근 | 주의점 |
|---|---|---|---|
| `r` | 어댑터 랭크 | 8, 16처럼 작은 값에서 시작해 필요시 증가 | 클수록 표현력과 메모리 증가, 과적합 위험 |
| `lora_alpha` | 스케일 배율(`α/r`) | `r`의 1~2배 정도를 시도 | `r`과 함께 학습률 영향이 달라짐 |
| `lora_dropout` | 어댑터 경로의 드롭아웃 | 0.0~0.1 범위에서 시도 | 데이터가 적을수록 과적합 방지 효과 |
| `target_modules` | 어댑터를 붙일 모듈 | 어텐션 투영부터 시작, 필요시 피드포워드로 확대 | 모델마다 이름이 다름 |

처음에는 어텐션의 `q_proj`와 `v_proj`에만 붙이는 구성이 논문 실험에서 널리 쓰였고, 이후 실무에서는 모든 선형 층에 붙이는 구성도 많이 시도됩니다. 붙이는 곳이 많을수록 표현력이 늘지만 메모리와 학습 시간이 늘고, 어느 쪽이 더 나은지는 데이터와 과제에 따라 달라서 정답이 없습니다. 위 표의 값은 출발점일 뿐이므로 검증 데이터 성능을 보며 조정해야 합니다.

## 실습 예시: Hugging Face PEFT로 LoRA 설정하기

1단계는 설치와 모듈 이름 확인입니다. 앞서 기반 기술에서 본 것처럼 모듈 이름은 모델마다 다르므로 먼저 출력해 봅니다.

## 하이퍼파라미터 탐색 설계

설정값이 여러 개이므로 무작정 바꾸면 무엇이 효과를 냈는지 알 수 없습니다. 한 번에 하나씩 바꾸되, 같은 데이터와 같은 난수 시드(seed)로 비교해야 합니다. 앞서 기반 기술에서 본 경사하강법의 보폭인 학습률이 가장 민감한 값이므로 먼저 정하고, 그다음 `r`과 `lora_alpha`, 마지막으로 `target_modules`와 드롭아웃을 조정하는 순서가 일반적입니다. 아래처럼 실험 계획을 표로 먼저 적어 두면 결과를 해석하기 쉽습니다.

| 실험 | 바꾼 값 | 고정한 값 | 확인할 지표 | 해석 기준 |
|---|---|---|---|---|
| E1 | 학습률 1e-4, 2e-4, 5e-4 | r=8, alpha=16, q·v만 | 평가 정확도, 학습 손실 곡선 | 손실이 튀면 학습률 과대 |
| E2 | r=4, 8, 16 | E1의 최적 학습률 | 평가 정확도, 어댑터 크기 | 정체되는 지점 선택 |
| E3 | alpha=r, 2r | E2의 최적 r | 평가 정확도 | 스케일이 학습 안정성에 주는 영향 |
| E4 | q·v만 vs 모든 선형 층 | E2·E3 최적값 | 평가 정확도, 학습 시간, 메모리 | 비용 대비 향상 판단 |

각 실험은 시드를 바꿔 두세 번 반복해서 변동 폭을 확인하는 것이 좋습니다. 같은 설정에서도 시드에 따라 점수가 몇 퍼센트 흔들리는 경우가 있어, 한 번의 결과로 설정 간 우열을 단정하면 잡음을 성과로 착각하기 쉽습니다. 평가 세트가 작다면 차이가 통계적으로 의미 있는지 신중히 봐야 합니다. 실험 기록은 설정, 시드, 데이터 버전, 결과를 한 줄로 남기는 간단한 표라도 있어야 나중에 재현할 수 있습니다.

실험이 쌓이면 가장 좋은 점수 하나만 고르고 싶어지지만, 평가 세트를 반복해서 보며 설정을 고르면 그 세트에 맞춰 과하게 튜닝(overfitting to the evaluation set)될 수 있습니다. 그래서 설정 선택에는 검증 세트를 쓰고, 최종 후보 하나만 한 번도 보지 않은 시험 세트로 마지막에 측정하는 구성이 안전합니다. 검증용과 시험용을 분리할 만큼 데이터가 없다면 최종 수치에 불확실성이 있다는 점을 보고서에 명시하세요.

```python
import json, time
def log_run(path, **kw):
    kw["ts"] = time.strftime("%Y-%m-%d %H:%M:%S")
    with open(path, "a", encoding="utf-8") as f:
        f.write(json.dumps(kw, ensure_ascii=False) + "\n")

log_run("runs.jsonl", exp="E2", r=16, alpha=32, lr=2e-4, seed=1,
        data="support-v3", eval_acc=0.0)   # eval_acc는 실제 측정값으로 채움
```

여기서 `eval_acc=0.0`은 자리 표시자이며, 실제 측정값으로 바꿔 기록해야 합니다. 이런 기록을 습관화하면 "그때 어떤 설정이었지"를 기억에 의존하지 않게 되고, 팀에서 결과를 공유할 때도 근거가 분명해집니다.

## 학습 데이터와 평가

미세 조정의 품질은 알고리즘보다 데이터가 좌우하는 경우가 많습니다. 입력과 기대 출력이 일관된 형식의 예시여야 하고, 중복·오타·정답이 서로 모순되는 예시를 정리해야 합니다. 개인정보가 섞인 데이터는 마스킹하거나 제외해야 하며, 학습 데이터에 들어간 내용을 모델이 그대로 출력할 수도 있다는 점을 고려해야 합니다. 데이터는 학습용과 평가용으로 분리하고, 평가용은 학습 중에 절대 보여 주지 않아야 합니다. 같은 문서의 일부가 양쪽에 섞이면 점수가 부풀려집니다.

평가는 손실값만이 아니라 실제 과제 지표로 해야 합니다. 분류라면 정확도·재현율, 생성이라면 사람이 정한 기준표나 정답 비교가 필요합니다. 그리고 미세 조정 전의 기본 모델과 프롬프트만 잘 다듬은 기본 모델도 같은 평가 데이터로 측정해서 비교해야 합니다. 프롬프트 개선만으로 충분하다면 미세 조정은 불필요한 비용입니다. 이 블로그의 LLM 평가 글에서 다룬 것처럼 고정된 평가 세트를 두고 변경 전후를 비교하는 습관이 여기서도 그대로 필요합니다. 또 특정 과제에 맞춰 조정하다가 원래 모델이 잘하던 일반 능력이 떨어지는 현상(catastrophic forgetting, 파국적 망각)이 있을 수 있으므로, 일반 질문 몇 가지로 퇴행 여부도 함께 확인합니다.

```python
# 평가 골격: 같은 평가 세트에 대해 기본 모델 / 프롬프트 개선 / LoRA 결과 비교
def accuracy(pred_fn, rows):
    ok = sum(1 for r in rows if pred_fn(r["text"]) == r["label"])
    return ok / len(rows)
print({"base": accuracy(base_predict, eval_rows),
       "base+prompt": accuracy(prompted_predict, eval_rows),
       "lora": accuracy(lora_predict, eval_rows)})
```

### 학습 데이터 형식 예시

분류나 지시 수행 과제의 학습 데이터는 보통 한 줄에 하나의 예시를 담는 JSON Lines(JSONL) 형식으로 준비합니다. 모델이 어느 부분을 정답으로 학습해야 하는지가 명확해야 하므로, 입력 지시와 기대 출력을 일관된 틀로 적습니다. 틀이 예시마다 다르면 모델이 형식 자체를 혼동해 평가 때 엉뚱한 출력을 낼 수 있습니다.

```json
{"prompt": "다음 문의를 결제/배송/계정/기타 중 하나로 분류하세요.\n문의: 카드 승인이 두 번 났어요", "completion": "결제"}
{"prompt": "다음 문의를 결제/배송/계정/기타 중 하나로 분류하세요.\n문의: 비밀번호 재설정 메일이 안 와요", "completion": "계정"}
```

위 예시는 형식을 보여 주는 가상의 문장입니다. 실제 데이터를 만들 때는 클래스별 개수가 크게 치우치지 않는지 세어 보고, 평가 세트와 문장이 겹치지 않는지 중복 검사를 합니다. 클래스가 한쪽으로 치우치면 모델이 가장 흔한 답만 내놓아도 정확도가 높아 보이는 착시가 생기므로, 정확도 하나만 보지 말고 클래스별 재현율을 함께 봐야 합니다. 또 사람이 붙인 라벨 사이에도 불일치가 있을 수 있으니, 일부를 두 사람이 따로 라벨링해 일치도를 확인하면 데이터 품질의 상한선을 가늠할 수 있습니다.

데이터 준비에서 자주 놓치는 것이 길이 분포입니다. 학습 예시가 대부분 아주 짧은데 실제 운영 입력은 길다면, 모델이 긴 입력에서의 행동을 배우지 못합니다. 입력 토큰(token, 모델이 텍스트를 쪼개 처리하는 단위) 길이의 분포를 학습 세트와 운영 로그에서 각각 집계해 비교하고, 최대 길이 설정이 운영 입력을 잘라 버리지 않는지도 확인하세요. 잘린 입력으로 학습하면 정답 근거가 사라진 채 라벨만 외우게 될 수 있습니다.

## QLoRA와의 관계

QLoRA(Quantized LoRA)는 2023년 Dettmers 등이 제안한 방법으로, 기본 모델의 고정된 가중치를 4비트로 양자화해 메모리에 올리고 그 위에 LoRA 어댑터를 학습합니다. 앞서 기반 기술에서 본 미세 조정의 메모리 구조 중 "고정된 원래 가중치" 부분을 줄이는 방법입니다. 논문은 이 방식으로 단일 GPU에서 매우 큰 모델도 미세 조정할 수 있다고 보고했습니다. 어댑터와 기울기는 더 높은 정밀도로 유지되므로 학습 가능한 부분의 품질을 지키면서 기본 모델 메모리만 줄이는 구조입니다.

대가도 있습니다. 4비트 양자화는 계산 오차를 만들 수 있고, 양자화와 역양자화 과정 때문에 학습 속도가 느려질 수 있습니다. 또 QLoRA로 학습한 어댑터를 정밀도가 다른 기본 모델에 병합할 때 결과가 약간 달라질 수 있으므로 병합 후 반드시 재평가해야 합니다. GPU 메모리가 부족해 LoRA조차 어려운 경우의 선택지이고, 메모리가 충분하다면 일반 LoRA가 더 단순합니다.

## 어댑터 배포: 병합과 다중 서빙

학습이 끝나면 어댑터를 쓰는 방법은 두 가지입니다. 하나는 병합(merge)입니다. `B·A`에 배율을 곱해 `W`에 더하면 어댑터가 사라지고 일반 모델 하나가 되므로, 추론 시 추가 계산 지연이 없습니다. 다른 하나는 어댑터를 분리해 둔 채 기본 모델에 붙여 쓰는 방식이며, 하나의 기본 모델 위에서 요청마다 다른 어댑터를 고를 수 있습니다.

```python
from peft import PeftModel
from transformers import AutoModelForCausalLM

base = AutoModelForCausalLM.from_pretrained("<BASE_MODEL_ID>", torch_dtype="auto")
model = PeftModel.from_pretrained(base, "adapters/support-classifier-v1")

merged = model.merge_and_unload()          # 어댑터를 가중치에 합쳐 일반 모델로
merged.save_pretrained("merged/support-classifier-v1")
```

| 방식 | 장점 | 단점 | 적합한 경우 |
|---|---|---|---|
| 병합 후 배포 | 추론 구조가 단순, 추가 지연 없음 | 용도마다 전체 모델 복사본 필요 | 용도가 하나이고 모델을 고정해 쓸 때 |
| 어댑터 분리 | 저장 공간 절약, 어댑터 교체 쉬움 | 서빙 엔진이 어댑터를 지원해야 함 | 팀·고객별 어댑터를 여러 개 운영할 때 |

vLLM 같은 일부 추론 서버는 LoRA 어댑터를 요청별로 선택하는 기능을 제공합니다. 지원 방식과 옵션은 버전마다 다르므로 해당 문서를 확인하세요. 어댑터 파일에는 학습 데이터의 영향이 들어 있으므로 어댑터도 모델과 같은 수준으로 접근 권한을 관리하고, 어떤 기본 모델·데이터·설정으로 만들었는지 이름 규칙(예: `support-classifier-v1`)과 기록을 남겨 두어야 재현할 수 있습니다.

### 추론 비용 관점

어댑터를 분리해 쓰면 추론 때 기본 모델 계산에 어댑터 계산이 더해지므로 약간의 추가 지연이 생길 수 있고, 병합하면 이 추가 계산이 사라집니다. 반대로 어댑터를 분리하면 하나의 기본 모델을 메모리에 올려 두고 여러 어댑터를 공유하므로 GPU 한 장으로 여러 용도를 서비스하기 쉽습니다. 어느 쪽이 유리한지는 요청 패턴(어댑터 종류 수, 요청량)과 서빙 엔진의 지원 방식에 따라 달라지므로, 실제 사용할 엔진에서 지연과 처리량을 직접 측정해 판단해야 합니다.

## 업무 예시: 고객 문의 분류 모델

다음은 설명을 위한 가상의 시나리오이며 실제 수행 결과가 아닙니다. 고객센터가 접수한 문의를 `결제`, `배송`, `계정`, `기타` 네 가지로 분류해 담당 팀에 자동 배정하려고 합니다. 먼저 기본 모델에 몇 개의 예시를 넣은 프롬프트만으로 평가 세트(예: 사람이 라벨링한 500건)에서 정확도를 측정합니다. 이 숫자가 요구 수준이면 미세 조정은 필요 없습니다. 부족하다면 사내 용어와 줄임말이 많아 프롬프트로는 한계가 있다고 판단하고, 학습용 데이터 수천 건을 개인정보를 마스킹해 준비합니다.

그다음 앞서 본 설정으로 `r = 8`부터 시작해 LoRA를 학습하고, `r = 16`과 `target_modules` 확대를 비교합니다. 평가 세트는 학습에 쓰지 않은 데이터로 고정하고, 클래스별 재현율까지 봅니다. `기타`로 쏠리거나 `결제`와 `계정`이 자주 혼동되는지 혼동 행렬로 확인하면 추가로 필요한 데이터를 알 수 있습니다. 성능이 기준을 넘으면 어댑터를 `support-classifier-v1`으로 저장하고, 기본 모델이 바뀌면 재학습이 필요하다는 점을 운영 문서에 적습니다. 마지막으로 낮은 신뢰도의 결과는 사람에게 넘기는 안전장치를 둡니다. 분류 오류가 곧바로 고객 불편으로 이어지기 때문입니다.

## 문제 점검 절차

| 증상 | 가능한 원인 | 확인·대응 |
|---|---|---|
| 학습 손실이 줄지 않음 | 학습률 부적절, 데이터 형식 오류, 레이블 마스킹 오류 | 소량 데이터로 과적합이 되는지 먼저 확인 |
| 학습 손실은 낮은데 평가 성능이 낮음 | 과적합, 학습·평가 분포 차이 | `r`·에폭 줄이기, 드롭아웃, 데이터 보강 |
| 일반 질문 능력이 떨어짐 | 좁은 데이터에 과하게 학습 | 에폭·학습률 낮추기, 일반 데이터 혼합 |
| 병합 후 결과가 달라짐 | 정밀도 차이, 병합 방식 | 병합 모델을 같은 평가 세트로 재평가 |
| 어댑터 로딩 오류 | 기본 모델 버전·구조 불일치 | 어댑터 설정의 기본 모델 이름·버전 확인 |
| 메모리 부족 | 배치 크기, 시퀀스 길이, 중간 계산값 | 배치 줄이기, gradient checkpointing, QLoRA 검토 |

가장 먼저 해 볼 일은 아주 작은 데이터(수십 건)로 학습해서 훈련 손실이 0에 가깝게 떨어지는지 보는 것입니다. 이것이 안 되면 모델이나 데이터 파이프라인의 구현 오류를 의심하고, 되면 규모를 키워 일반화 문제로 넘어갑니다.

```bash
# 학습 중 GPU 메모리 확인
nvidia-smi --query-gpu=memory.used,memory.total --format=csv -l 5
# memory.used [MiB], memory.total [MiB]
# 21034 MiB, 24576 MiB
```

## 한계와 적용 기준 Q&A

### Q. LoRA로 모델에 새로운 지식을 넣을 수 있나요?

A. 어느 정도는 가능하지만 한계가 있습니다. 미세 조정은 새 사실을 안정적으로 주입하기보다 말투, 출력 형식, 과제 수행 방식을 익히는 데 더 강하다고 알려져 있습니다. 자주 바뀌는 사실 정보는 검색 증강(RAG, Retrieval-Augmented Generation)으로 최신 문서를 근거로 제공하는 편이 갱신과 출처 확인에 유리합니다. 이 블로그의 파인튜닝과 RAG 비교 글도 함께 보세요.

### Q. rank를 크게 하면 항상 좋아지나요?

A. 아닙니다. 어느 수준 이상에서는 성능 향상이 미미한 반면 메모리와 과적합 위험은 늘 수 있습니다. 작은 값에서 시작해 검증 성능이 정체되는 지점을 찾는 것이 합리적이며, 과제 난이도가 높을수록 더 큰 값이 필요할 수 있습니다.

### Q. 어댑터를 여러 개 합쳐 쓸 수 있나요?

A. 라이브러리가 여러 어댑터를 가중 합치는 기능을 제공하지만, 어댑터끼리 서로 간섭해 품질이 떨어질 수 있으므로 합친 결과를 반드시 평가해야 합니다. 어댑터를 요청별로 전환하는 방식이 더 안전한 경우가 많습니다.

### Q. 학습 데이터가 얼마나 있어야 하나요?

A. 정해진 숫자는 없습니다. 과제가 단순하고 형식 학습이 목적이면 수백~수천 건으로도 효과를 보는 경우가 보고되지만, 데이터 품질과 과제에 크게 좌우됩니다. 적은 데이터로 시작해 학습 곡선과 평가 성능으로 추가 필요성을 판단하세요.

### Q. 도입 전 체크리스트가 있나요?

A. 아래를 확인하세요.

- 프롬프트 개선과 RAG만으로 해결되지 않음을 평가 세트로 확인했는가
- 기본 모델의 라이선스가 미세 조정과 결과물 배포를 허용하는가
- 학습 데이터의 개인정보·저작권 문제를 정리했는가
- 학습·평가 데이터를 분리하고 평가 세트를 고정했는가
- 병합 전후, 기본 모델 대비 일반 능력 퇴행을 확인했는가
- 어댑터와 기본 모델 버전, 설정, 데이터 출처를 기록하는가

## 마무리

LoRA의 핵심은 "가중치 변화량은 저랭크로 충분하다"는 가정 아래 원래 모델을 고정하고 작은 두 행렬만 학습한다는 것입니다. 그 덕분에 학습 메모리와 저장 공간이 줄고 용도별 어댑터를 바꿔 끼울 수 있습니다. 하지만 메모리가 전부 사라지는 것은 아니고, 지식 갱신에는 RAG가 더 맞을 수 있으며, 평가 없이는 개선 여부를 알 수 없습니다. 먼저 평가 세트를 만들고, 작은 `r`로 시작해 비교하는 것에서 출발해 보세요.
